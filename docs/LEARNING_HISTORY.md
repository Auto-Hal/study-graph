# 3科目共通の学習履歴

2026-10-08。保存が完了した回答を、くずし字・西洋美術史・西洋哲学史で同じ画面から振り返る。

## 利用場面

- `/history` を「今日」「復習」「各科目の教材」「回答後の結果」から開く。
- 科目・単元・学習した日（日本時間）を選ぶ。「要再確認の回答だけ」で、不正解または自己評価が「もう一度・難しい」の回答を絞る。説明問題を自動で不正解と判定する条件ではない。
- 新しい順に30件ずつ表示する。回答の詳細では、当時の問題・自分の回答原文・短答の判定、または説明の自己評価・評価基準と見本を読む。
- 詳細から同じ単元の概要、科目の教材、Notionの元教材、今日の復習予定へ進む。単元の概要を開くだけでは問題を発行しない。
- 読み取りが失敗した場合は「取得できません」と再読み込みボタンを表示する。取得失敗を履歴0件として扱わない。

説明問題は、空白・改行を含む保存済みの原文と、回答時の評価基準を表示する。一言一句の一致で正誤を付けない。既存の自己評価を履歴画面から変更したり、現在の教材に合わせて再採点したりしない。

## 保存と復習予定の区別

履歴に表示するのはサーバー保存済みの回答。端末だけにある未同期回答は、既存の同期・復旧画面で確認する。

- 単元は追加練習なので、回答・自己評価を保存しても日々の復習予定を動かさない。
- 「回答当時の次回予定」と「この学習項目の保存済み予定」を区別する。後者は他の回答で変わることがあり、現在の範囲・出題設定で取り組めることを保証する表示ではない。取り組む入口は `/review`。
- 保存理由は受領結果の `reason` / `srsReason` を優先する。旧 `exercise_attempts.srs_reason` の互換分類だけから復習予定への反映を推測しない。
- 一覧・詳細・絞り込み・再読み込みでは、問題発行、回答保存、復習予定、復習機会を変更しない。画面から既存の回答送信処理を呼ばない。

## 以前の形式の記録

旧 `public.review_attempts` も既存の個人用アプリトークンで読み取る。保存版の記録に対応付く旧履歴は重複表示しない。大きい履歴IDは `legacy-` を付けた文字列で扱い、JavaScriptの数値精度で壊さない。

当時の問題本文・解説が保存されていない旧記録は、その制約を明記する。現在のsnapshotから項目名と科目を一意に確認できる場合だけ補足する。文字・誤読はくずし字として扱い、知識項目の科目が確認できない場合は「科目未確認（旧形式）」に残す。残っている回答原文と当時の自己評価は表示する。欠けている問題や原文は作り直さない。

## 実装境界

| 責務 | ファイル |
| --- | --- |
| 日付・条件・日時精度・保存版の読取検証 | `src/lib/history/core.ts` |
| サーバーの資格情報で読取RPCを1回呼ぶ | `src/lib/history/runtime.ts` |
| 一覧と当時の回答詳細 | `app/history/page.tsx`、`app/history/[recordId]/page.tsx` |
| 絞り込みと読取の再試行 | `HistoryFilters.tsx`、`HistoryRefreshButton.tsx` |
| 所有者を限定した読取・旧形式の重複抑止 | `supabase/migrations/20261007233000_learning_history_read.sql` |

24番目のmigrationは、履歴の読取RPC、利用者・日時順の索引と旧履歴の対応付けを探す索引だけを追加する。既存23ファイル、回答・採点・SRSのwriter、資格情報、Notion教材は維持する。RPCは `STABLE`、`SECURITY DEFINER`、`search_path=pg_catalog`、全テーブルをschema修飾し、実行権限を `service_role` のみに限定する。privateテーブルの直接読取権限は追加しない。

保存版の回答はサーバー設定のlearnerに限定する。旧形式は従来の単一アプリの記録であり、存在しないlearner所有権を推測しない。既存アプリトークンをサーバーで検証する。秘密値はクライアントへ渡さず、エラーや画面にも出さない。

一覧は回答原文・問題のpayloadを返さず、詳細の要求時だけ返す。日時とIDによるページ分けで、同じ時刻の回答も重複・欠落を防ぐ。PostgRESTのマイクロ秒を文字列のまま次ページへ渡す。日本時間の日付の終了境界は翌日0時を含めない。

## 検証と反映順

型検査、全unit/contract、隔離PostgreSQL、[ブラウザ試験](BROWSER_E2E.md)とCIを確認する。DBでは利用者・予定の分離、日付境界、同時刻のページ分け、大きい旧ID・重複抑止、原文、実行権限の拒否を検査する。すべての履歴RPCを読み取り専用transactionで実行し、16テーブルの内容が前後で一致することを確認する。

本番は、学習データの件数・内容hashを取得 → additive migration適用 → 権限・実HTTP読取確認 → コード反映 → READYと稼働SHA → 画面読取と件数・hash再照合の順序とする。実機Safariと通信なしでの起動は別の確認として残す。

コードを前版へ戻す場合、追加した関数・索引は残しても旧版に影響しない。学習データの削除や再採点は不要。問題がある場合はまずコードを戻し、DB定義を不用意に削除しない。
