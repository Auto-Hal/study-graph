# 次の開発サイクルと個人利用の到達条件

更新: 2026-10-07。既存の Phase 番号は実装・DB契約の履歴として維持し、今後の順序は本書に従う。

## 合意済みの方針

- 個人専用。くずし字・西洋美術史・西洋哲学史に優劣を付けず、3科目を小さい単位で育てる。
- Notion が教材の正本、Supabase が回答・復習予定の正本。資格情報を教材やテスト成果物に含めない。
- 美術史には美術検定の観点を含める。作品・作者・様式・時代・背景を結び付ける教材を目指す。
- 哲学史の説明・比較を一言一句の一致で採点しない。用語短答の照合と、説明の評価を区別する。
- 認証は個人利用に必要な最小限。既存のアクセス制限を調べ、必要なら端末で保持する共有パスワードを検討する。複数利用者のアカウント管理は当面対象外。
- 今回の開発では本番DB・Notion・Vercelを変更しない。

## 到達条件（目標の具体化は仮案）

最初の実用状態: スマートフォンで5〜15分、科目を選んで学び、回答し、保存結果と次回予定を確かめられる。3科目それぞれ最低1単元、5〜10問を目安にする。通信の失敗後も回答が残り、再開時に1回だけ保存される。説明問題は評価基準を読んで自己評価できる。最小のバックアップ・復元手順がある。

完成状態: くずし字を字形から短文・実資料へ、美術史を作品識別から美術検定の知識と背景の説明へ、哲学史を用語から自分の言葉による説明・比較へ進められる。履歴から弱点を選び、必要な復習を続け、教材追加と障害からの復元を自力で行える。範囲・問題数・検定級は未確定。

哲学史の説明評価は「必要な要点」「許容する言い換え」「重大な誤解」を教材に記録する。初期版は見本と基準による自己評価。自動意味判定は正答・部分正答・誤答・判定困難の例を集め、言い換えの誤判定を測ってから導入する。判定困難を不正解として確定しない。

## 今回の優先作業と成果物

1. **差分保全と計画反映**: 環境整備の差分・履歴、本書と環境手順。既存の変更を失わず、新規開発と区別できること。
2. **隔離E2E環境**: 固定Notion教材、使い捨てPostgreSQL、別ポートのNext.js、ブラウザrunner。本番の資格情報を読み込まず、既存の22 migrationとRPCを実行すること。
3. **3科目の正常な保存**: 復習入口→回答→評価→保存結果と次回予定。390px/820pxで回答・状態・DBの一致を確認すること。
4. **二重操作と通信失敗からの復旧**: 送信前失敗、受理後の応答消失、ブラウザ終了・再起動、同一要求の再送。回答IDを維持し、履歴1件・SRS適用1回になること。
5. **今日・復習入口と予定の一致**: legacyの候補数とObjectiveの予定を混同しない読取モデル。3科目で期限内/未学習/取得不可を区別し、入口から実際に出題可能な内容へ移れること。

今回のブラウザ検証は固定教材各1問を使う。説明の意味評価、美術検定教材の拡充、全Objectiveの教材内容、実際のNotion・hosted SupabaseのHTTP境界、iPhone/iPad実機、サービスワーカーによる通信なしの起動は別の検証として残す。ブラウザの画面サイズ検証を実機検証と呼ばない。
