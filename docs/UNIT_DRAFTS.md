# 単元練習の下書きと再開

更新: 2026-10-11。対象は `/units` の6単元。通常の「今日の復習」やオフラインpilotの入力途中は今回の対象に含めない。

## 利用場面

文章を書いている途中で単元の概要へ戻ったとき、画面を再読み込みしたとき、ブラウザを終了したときも、同じブラウザ・同じアプリのURLから「途中から再開」で続ける。短答の入力、自由な説明の改行・空白、「回答する」の後でまだ自己評価を選んでいない解答表示を復元する。

下書きと確定済み回答を画面で区別する。「下書きをこのブラウザに保存しました」は端末だけの保存。「できた」などの自己評価を選ぶと既存の回答outboxへ確定し、通信が可能になればSupabaseの履歴へ同期する。説明の自動正誤判定は行わない。

## 保存の境界

- 入力イベントと解答表示の操作内で、小さい版付きデータをlocalStorageへ同期的に書く。タイマーや画面終了時の処理を待たない。最後の文字を消した状態も保存する。
- 単元ID、練習の組のID、発行済み問題ID、exercise IDを照合する。別の組や別の問題の文章を混ぜない。データは回答原文、解答を表示したか、回答にかかった時間だけであり、回答ID・自己評価・正誤・復習予定を確定しない。
- 再開位置はIndexedDBの回答outboxだけから決め、その次の未確定問題の下書きを読む。自己評価のoutbox保存完了後に該当下書きを消す。サーバーの同期完了を待って消す設計にはしない。削除できず古い下書きが残っても、確定済み回答を優先する。
- 再開前に下書きを読み出せない、版や内容が不正な場合は、空の入力欄で上書きせず概要へエラーを出す。下書きの保存に失敗した場合は入力を画面に残し、「保存できません」と表示する。文章のコピーと「下書きを保存し直す」で回復できる。
- 回答時間は保存した経過時間と再開後の操作時間を使う。ブラウザを閉じていた時間を即答/難しいの推奨評価に加算しない。

既存の単元の組のIndexedDB形式は変更しない。DB schema、教材の保存版、Notion、Supabaseの資格情報、復習予定も変更しない。

## 制約

下書きは同じブラウザの保存領域に限る。別端末・別ブラウザへの引継ぎ、保存領域を消した後の復元、端末内下書きのバックアップには対応しない。Supabaseの学習バックアップは確定・同期済みの回答を扱う。ブラウザの保存領域が無効・容量不足の場合に保存成功とは表示しない。

同じ問題を複数のタブで同時編集した場合は最後の書き込みが下書きになる。共同編集やタブの下書き競合の解決は対象外。確定済みの回答は、既存の同じ問題ID・回答IDの保存契約に従う。Safari実機と通信なしでのアプリ起動は別の検証として残る。

## 実装と検証

`src/lib/review/units/draft-store.ts` が原文と版の照合、保存、読み取り、削除を担当する。`StudyUnitPractice.tsx` はoutboxの回答済み位置を先に読み、`ReviewSession.tsx` は入力イベント、解答表示、確定後の削除をつなぐ。

unitテストは原文の空白・改行、解答表示、組と問題の分離、全消去、不正な版・内容、容量不足・読み取り拒否・削除失敗、再試行を確認する。`scripts/e2e/unit-drafts.mjs` は隔離したPostgreSQLとChromiumで、3科目×390px/820pxの復元6ケースと、3科目の保存失敗・再試行・不正な下書きの読み取り3ケースを追加する。

ブラウザの完了条件は、入力直後の再読み込み・概要への離脱・同じprofileの再起動で原文と解答表示が戻ること、自己評価前には新しい回答やSRSが書かれないこと、自己評価後には原文が1件だけ保存されること、古い下書きより確定済みの位置を優先すること。説明は復元後も`ungraded`/`isCorrect=null`であること。実行方法は [ブラウザ検証](BROWSER_E2E.md)。
