# 復習開始の待ち時間

2026-10-08。利用者から「取り組む」を押して問題が表示されるまで数秒かかるとの報告を受けて調査した。

## 確認した事実

本番の処理リージョンは米国 iad1、Supabaseは東京 ap-northeast-1。美術史・哲学史は各問題の保存版登録3回、発行1回、保存版の読取1回を、全問題について直列で待っていた。くずし字も教材・予定・保存版・発行の通信を待つ。ブラウザで390pxの復習画面表示を測定すると、くずし字5.04秒、美術史17.35秒、哲学史7.57秒だった。端末・ネットワーク・サーバー初期化により時間は変わる。

## 改善

- Vercelの実行場所をDBと同じ東京 hnd1 に指定する。[公式のリージョン設定](https://vercel.com/docs/functions/configuring-functions/region)と[地域一覧](https://vercel.com/docs/regions)に従う。
- 独立した問題の準備を最大3問まで重ねる。各問の登録→発行→保存版の照合という順序と、利用者へ返す出題順は維持する。通常の復習と単元の開始に同じ上限を使う。
- ある問題が期限前、対象外、取得不可でも、通常の復習では他の問題を妨げない。単元で処理が失敗した場合は新たな準備を止め、進行中の処理が終了してからエラーを返す。
- 「取り組む」にはクリック直後の「準備中…」を表示し、既存の読み込み画面にも準備中であることを明示する。

現在のNotion教材と予定をその都度確認する方式を維持する。画面先読みから問題を発行せず、期限や採点・回答の再送契約を変更しない。DB migration、資格情報、Notionへの書き戻しを追加しない。

## 検証

上限3問・順序・失敗後の処理終了をunitテストで確認する。既存の各科目のScope、保存版、期限前、取得不可、回答の再送検証も実行する。[ブラウザ検証](BROWSER_E2E.md)は40ケースで、通信待ちのクリック表示3ケースを追加する。

本番反映後はリージョンとコミットを確認し、同じ復習入口から再計測する。計測では問題の開始まで進めるが回答・評価は送信せず、前後の回答履歴と復習予定を照合する。実機Safariの時間は別の確認として扱う。
