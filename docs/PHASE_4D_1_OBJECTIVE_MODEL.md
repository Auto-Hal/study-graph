# Phase 4D-1 Objective model

Phase 4D-1 adds only the Git-owned Objective model. An Objective is an
evaluable capability for a specific target, action/direction, response mode,
task condition, and success criterion. Its SRS epoch identifies an SRS
generation; an SRS state is a review schedule and is not a mastery claim.

## Identity and version

`objectiveId` is a stable, human-readable semantic identity. A rename that
does not change the capability keeps the ID and may create a new
`objectiveVersion`. A change to target, direction, response mode, conditions,
or success criterion requires a new Objective identity. `srsEpoch` starts at
`1`; it is validated as a positive integer and is kept beside the semantic
definition so an incompatible SRS generation can start without rewriting old
state.

Recognition, recall, and production are separate response modes. Reverse
directions, single-character versus in-context reading, choice versus free
short answer, and reading versus mother-character knowledge are separate
Objectives unless a human review establishes that the evaluated capability is
actually identical.

## Pilot definition and binding

The pilot Objective remains:

```text
kuzushiji.a.eitaigura-u3042-00032-1.read
```

It means reading the one fixed Japanese Eitaigura source glyph as `あ` from a
context-free, hint-free, single-character image using a short recall answer.
It does not mean reading all `あ` glyphs, reading in context, selecting from
choices, or identifying the `阿` mother character. The existing `阿` annotation
remains the PR #27 `legacy-approved` content metadata and is not added to the
Objective meaning.

The pilot binding uses `evidenceUse: "srs"`. Git does not contain the UUID
generated by the Phase 4C Supabase archive, so `revisionId` is the existing
immutable pilot `contentHash`. A later archive layer can map this exact Git
reference to its database `revision_id`; Phase 4D-1 does not invent or query a
database identifier.

An ExerciseRevision has at most one Objective binding in this phase. Changing
the binding requires a new ExerciseRevision; no existing revision or attempt
is mutated. `practice-only` bindings are allowed by the pure model but do not
authorize Objective SRS updates.

## Canonical hash

Objective canonicalization reuses the Phase 4C canonical JSON helper without
changing ExerciseRevision or ContentRelease hashing. Object keys are sorted,
array order is preserved, strings are unchanged, and undefined/non-finite
values are rejected. The resulting explicit UTF-8 canonical string is hashed
with SHA-256. Objective fields, including version and epoch, therefore have a
deterministic content hash; field ordering does not affect it.

## Boundary

This phase has no Supabase migration, Objective table, RPC, runtime cutover,
queue change, Review UI change, legacy SRS migration, authentication change,
Notion write, or offline implementation. Phase 4C revision/release hashes,
pilot grading, instance issuance, receipt semantics, SRS behavior, and scope
behavior remain unchanged.
